# FreelyRSS 实施计划

## 目标

本计划将 FreelyRSS 从当前“文档优先、尚未脚手架”的状态，推进到可交付的桌面优先产品，并为后续 Web、移动端、同步、AI 与扩展能力预留清晰路径。

## 执行原则

- 先固化架构文档与数据库 schema，再开始代码实现。
- 先交付桌面端核心离线阅读器，再扩展同步、AI、Web 和移动端。
- 规则、搜索、智能文件夹必须共用统一查询表达式模型。
- 同步只同步实体变更与事件日志，不同步 SQLite 文件。
- 身份模型采用多模式并存，但以“账号 + 设备”为核心，匿名模式仅作为离线或自托管补充。
- Web 端是同步数据的远程访问入口，天然依赖账号体系，不承担桌面端“本地优先”的核心约束。
- API 分为“本地桌面 API”和“远程同步 API”两层，二者职责与部署位置不同。
- 每完成一个大阶段，都要更新 `memory-bank/architecture.md` 和 `memory-bank/progress.md`。

## 阶段 0：文档基线

### Step 1. 补全架构基线文档
- 操作：在 `memory-bank/architecture.md` 中补齐系统目标、分层架构、模块边界、平台策略、阶段路线图，并明确桌面端是首个完整交付平台。
- 验证测试：打开 `memory-bank/architecture.md`，确认文档不再为空，且包含“核心离线层、可选在线层、可选智能层”三层结构说明。

### Step 2. 在架构文档中落完整数据库 schema
- 操作：把设计文档中的完整实体模型整理进 `memory-bank/architecture.md`，至少覆盖 `Feed`、`Folder`、`Tag`、`FeedTag`、`ArticleTag`、`Article`、`Attachment`、`UserState`、`Annotation`、`Rule`、`SmartFolder`、`AIArtifact`、`SyncEvent`。
- 验证测试：逐项核对架构文档，确认以上 13 个实体全部出现，且字段名与设计文档一致。

### Step 3. 固化首个可交付版本边界
- 操作：在 `memory-bank/architecture.md` 中新增“Release 1 范围”部分，明确首发包含高亮与批注、PDF 导出、Markdown / HTML 导出、批量导出、播客附件与播放器、智能文件夹；同时明确首发不包含官方同步、Web、移动端、AI、本地桌面 API 和团队协作。
- 验证测试：检查 `memory-bank/architecture.md`，确认首发范围与非目标写清楚，并且首发包含项与排除项都可单独列出。

### Step 4. 初始化项目进度文档
- 操作：在 `memory-bank/progress.md` 中创建里程碑清单、状态字段、更新时间和风险记录区，用来跟踪每个实施阶段。
- 验证测试：打开 `memory-bank/progress.md`，确认文件不再为空，且至少包含“阶段名称、状态、最近更新、风险/阻塞”四类信息。

## 阶段 1：仓库与工程骨架

### Step 5. 建立 monorepo 目录骨架
- 操作：按技术栈文档创建 `apps/`、`packages/`、`crates/` 顶层目录，并预留 `apps/desktop`、`apps/web`、`apps/mobile`、`apps/sync-server`、`packages/ui`、`packages/shared-types`、`packages/shared-query`、`packages/shared-config`、`crates/core-domain`、`crates/feed-engine`、`crates/content-pipeline`、`crates/rule-engine`、`crates/search-engine`、`crates/sync-engine`、`crates/integration-engine`。
- 验证测试：查看仓库目录树，确认目录结构与技术栈文档建议结构一致，没有把全部逻辑塞进单一应用目录。

### Step 6. 建立 JS/TS 与 Rust 工作区
- 操作：初始化 `pnpm workspace` 和 `Cargo workspace`，使桌面端、Web 端、共享包和 Rust crates 能在单仓中统一管理。
- 验证测试：运行工作区级依赖解析与包发现流程，确认所有预期 package/crate 都能被识别。

### Step 7. 确定统一代码规范
- 操作：选定一套前端格式化与 lint 方案，并补齐 Rust 的格式化与静态检查约束，同时定义提交前检查规则。
- 验证测试：对空模板或占位文件执行格式化与静态检查，确认检查器能运行且不会相互冲突。

### Step 8. 建立变更集与版本管理流程
- 操作：配置 changesets、版本号策略和变更记录规则，区分客户端版本、协议版本和数据库 schema 版本。
- 验证测试：创建一次示例变更记录，确认版本变更流程可以生成预期的发布说明草稿。

### Step 9. 建立基础 CI 流程
- 操作：添加最小可用 CI，覆盖前端依赖安装、Rust 编译、测试、lint 和文档链接检查。
- 验证测试：在干净环境中触发 CI，确认所有基础任务能跑通，且失败信息可定位到具体阶段。

### Step 10. 定义配置与环境变量边界
- 操作：在 `packages/shared-config` 中定义运行环境、代理设置、同步配置、AI 配置和实验性开关的来源与优先级，并写入文档。
- 验证测试：使用桌面开发环境和测试环境分别启动配置读取流程，确认缺失配置会报出明确错误，而不是静默回退。

## 阶段 2：桌面壳与共享包基础

### Step 11. 初始化桌面应用壳
- 操作：在 `apps/desktop` 中搭建 Tauri + React + TypeScript + Vite 基础壳，先确保应用可启动、可加载空白主界面。
- 验证测试：启动桌面应用，确认窗口正常打开，且没有依赖网络即可进入主界面。

### Step 12. 建立共享 UI 基础包
- 操作：在 `packages/ui` 中建立基础设计系统，只包含布局容器、按钮、输入、列表容器、分栏结构和主题变量，不引入重型后台模板。
- 验证测试：在桌面壳中渲染一组基础组件，确认样式来源统一，且主题变量可以生效。

### Step 13. 建立共享类型包
- 操作：在 `packages/shared-types` 中定义前端需要消费的核心领域类型、DTO 和状态枚举，避免各应用重复定义。
- 验证测试：让桌面端引用共享类型，确认类型可被正确导入，且不存在循环依赖。

### Step 14. 建立共享查询表达式包
- 操作：在 `packages/shared-query` 中定义规则、搜索、智能文件夹共用的 AST、序列化规则和校验边界，并同时支持“可视化构造器 -> AST”“文本查询 -> AST”“AST -> SQL 查询计划”的转换。
- 验证测试：用同一组条件分别从可视化构造器和文本查询生成 AST，确认两种输入最终生成等价的查询结构。

### Step 15. 实现三栏主布局
- 操作：搭建左栏订阅树、中栏文章列表、右栏阅读面板的基本布局，只先放空状态与占位内容。
- 验证测试：打开桌面应用，确认三栏布局稳定显示，并在窄窗口下不会完全破碎。

### Step 16. 建立导航与视图状态框架
- 操作：接入路由、局部 UI 状态和异步数据状态管理，明确“当前来源”“当前过滤条件”“当前选中文章”的来源。
- 验证测试：在空数据状态下切换不同导航入口，确认状态变化不会导致页面重载或出现无效引用。

### Step 17. 建立键盘与可访问性基础设施
- 操作：定义全局快捷键映射、焦点顺序、ARIA 语义和高对比度主题入口，先覆盖主布局和主导航。
- 验证测试：只使用键盘进入三栏主要区域，确认焦点顺序合理，且屏幕阅读器能读出主要区域名称。

## 阶段 3：本地数据层与领域模型

### Step 18. 选定数据库迁移方案
- 操作：建立 SQLite schema migration 机制，并明确升级、回滚、失败恢复和备份策略。
- 验证测试：在空数据库上执行初始化迁移，在已有数据库上重复执行迁移，确认流程幂等且不会破坏现有数据。

### Step 19. 实现核心业务表
- 操作：先创建不依赖高级功能的基础业务表，包括 `Feed`、`Folder`、`Tag`、`FeedTag`、`ArticleTag`、`Article`、`Attachment`、`UserState`、`Annotation`、`Rule`、`SmartFolder`、`AIArtifact`、`SyncEvent`。
- 验证测试：检查初始化后的数据库结构，确认所有表都存在，字段命名与架构文档完全一致。

### Step 20. 补齐索引与约束
- 操作：为主键、唯一键、外键和常用查询字段补齐约束与索引，优先覆盖 `feed_url`、`source_guid`、时间字段、状态字段和关联表。
- 验证测试：向数据库写入重复订阅地址、无效外键和非法状态值，确认数据库会拒绝不合法写入。

### Step 21. 建立全文搜索表与同步更新机制
- 操作：建立 FTS5 表，并定义文章标题、摘要、正文和部分元数据的入索引策略及更新方式。
- 验证测试：插入一组样例文章后执行搜索，确认标题命中与正文命中都能返回结果。

### Step 22. 建立本地缓存目录结构
- 操作：将数据库文件、正文缓存、媒体缓存、导出产物和日志存储路径分层，避免所有数据混在同一目录。
- 验证测试：运行应用后检查本地工作目录，确认不同类型的数据落在约定位置，而不是临时散落。

### Step 23. 准备标准化测试数据集
- 操作：建立覆盖 RSS、Atom、JSON Feed、富媒体文章、重复文章、缺字段文章、长文、不同语言文章的样例数据集。
- 验证测试：对测试数据集做清单核对，确认每种关键场景至少有一个固定样本。

### Step 24. 建立 Rust 领域模型
- 操作：在 `crates/core-domain` 中定义与数据库 schema 对齐的核心实体、值对象和状态枚举，并明确前端可见与内部专用字段。
- 验证测试：执行领域模型到数据库记录的往返转换测试，确认不会丢字段或误改字段含义。

## 阶段 4：订阅抓取与源管理

### Step 25. 建立抓取器抽象
- 操作：在 `crates/feed-engine` 中定义 HTTP 获取、解析、标准化和持久化之间的边界，避免把抓取逻辑直接写进 UI。
- 验证测试：对抓取器做空实现接线测试，确认 UI 和调度层可以在没有真实网络请求时完成调用链闭环。

### Step 26. 支持 RSS 与 Atom 解析
- 操作：先完成 RSS 2.0、RSS 0.9x 与 Atom 1.0 的解析和标准化输出。
- 验证测试：用固定样例 feed 执行解析，确认标题、链接、发布时间、作者和正文入口能稳定落表。

### Step 27. 支持 JSON Feed 解析
- 操作：补齐 JSON Feed 解析路径，并保证其输出与 RSS/Atom 最终归一到同一文章模型。
- 验证测试：导入 JSON Feed 样例，确认生成的订阅源与文章在 UI 中可正常显示。

### Step 28. 支持网页 feed 自动发现
- 操作：实现从普通网页 HTML 中发现 feed 链接的能力，并区分“自动发现多个候选源”和“未发现任何源”的结果。
- 验证测试：输入已知带 feed 链接的网页和普通网页各一组，确认返回结果与预期一致。

### Step 29. 实现订阅源持久化流程
- 操作：把新建订阅、解析结果写入 `Feed` 与 `Article` 相关表，并补齐首次抓取后的状态初始化。
- 验证测试：手动添加一个订阅源后，确认数据库中存在对应 `Feed` 记录，并且文章列表能显示首批文章。

### Step 30. 实现去重规则
- 操作：按“canonical URL / 原始 URL、标题+时间+来源、内容哈希”的优先级实现去重，避免重复文章污染列表。
- 验证测试：导入包含重复文章的样本，确认最终文章库中的记录数小于原始输入条数，且不会误删不同文章。

### Step 31. 实现增量抓取与缓存头支持
- 操作：支持 `ETag`、`Last-Modified`、更新频率和失败后的重试策略，避免每次全量重抓。
- 验证测试：连续两次抓取同一源，确认第二次请求会复用缓存头，且无更新时不会重复写入文章。

### Step 32. 建立源健康状态与错误分类
- 操作：区分网络错误、解析错误、权限错误、内容为空和连续失败等状态，并把结果回写到 `Feed` 健康字段。
- 验证测试：对无效地址、超时地址和格式错误地址分别抓取，确认 UI 中显示不同错误类型。

### Step 33. 建立订阅树与分组管理 UI
- 操作：实现文件夹、标签、分组和排序的基本界面，先支持查看、展开、折叠和选中。
- 验证测试：创建多个文件夹和订阅源后，确认左栏能按层级稳定显示，切换节点会刷新中栏文章列表。

### Step 34. 实现订阅源编辑操作
- 操作：支持重命名、自定义显示名、更新频率设置、图标更新和手动刷新。
- 验证测试：编辑一个订阅源后重新打开应用，确认修改结果仍然存在。

### Step 35. 实现 OPML 导入
- 操作：支持从 OPML 批量导入文件夹结构和订阅源，并给出重复源处理策略。
- 验证测试：导入包含嵌套文件夹和重复源的 OPML 文件，确认层级被保留，重复项不会被重复创建。

### Step 36. 实现 OPML 导出
- 操作：支持把当前订阅树导出为可被其他 RSS 阅读器识别的 OPML 文件。
- 验证测试：导出后重新导入同一文件，确认订阅源数量和层级结构与导出前一致。

## 阶段 5：阅读体验与文章状态

### Step 37. 建立文章列表查询流程
- 操作：把“当前来源、当前过滤条件、当前排序规则”组合成统一查询入口，驱动中栏文章列表。
- 验证测试：在多个来源、多个状态混合的数据下切换筛选条件，确认列表结果与筛选条件一致。

### Step 38. 实现文章列表虚拟滚动
- 操作：为长列表接入虚拟滚动，保证万级文章下滚动和切换仍然稳定。
- 验证测试：导入大体量测试数据后滚动文章列表，确认不会出现明显卡顿或一次性渲染全部记录。

### Step 39. 建立阅读面板基础视图
- 操作：在右栏显示文章标题、来源、作者、发布时间、摘要和正文容器，先打通从列表选中到阅读渲染的链路。
- 验证测试：点击不同文章时，确认右栏内容会即时切换，且不会残留上一条文章的数据。

### Step 40. 实现原始内容与提取内容切换
- 操作：为每篇文章提供“原始内容”和“正文提取内容”两种阅读模式，并记住用户最近一次选择。
- 验证测试：切换同一文章的两种模式，确认视图确实变化；重开应用后，最近的模式选择仍被保留。

### Step 41. 实现正文提取管线
- 操作：在 `crates/content-pipeline` 中实现 HTML 清洗、正文提取、缩略图识别和语言/字数估算。
- 验证测试：用结构复杂和结构简单的文章样例分别提取，确认主要正文被保留，导航和广告噪音被明显压缩。

### Step 42. 支持附件与播客 enclosure
- 操作：识别文章中的附件元数据，区分图片、音频、视频和其他文件，并写入 `Attachment`。
- 验证测试：导入带 enclosure 的播客 feed，确认文章详情中能看到音频附件信息。

### Step 43. 实现文章状态写入
- 操作：实现已读、未读、星标、喜欢、重要程度、稍后读和阅读进度的本地写入与回显。
- 验证测试：修改文章状态后刷新界面或重启应用，确认状态没有丢失。

### Step 44. 实现键盘阅读流
- 操作：支持上下移动文章、打开文章、标记已读、切换星标、切换面板焦点等核心快捷键。
- 验证测试：只用键盘完成“选中文章、打开、标记已读、切换下一篇”的完整流程，确认无需鼠标介入。

### Step 45. 实现阅读主题与排版设置
- 操作：支持亮色、暗色、高对比度、字体、字号、行距和边距设置，并将这些设置持久化。
- 验证测试：修改排版设置后重启应用，确认阅读区域样式保持不变，且高对比度模式下文本仍可读。

### Step 46. 实现高亮与批注
- 操作：在阅读面板中支持选中文本后创建高亮、笔记和批注锚点，并写入 `Annotation`。
- 验证测试：为同一文章创建多条高亮和笔记后重新打开文章，确认所有标注都能回显到正确位置。

## 阶段 6：规则、智能文件夹与搜索

### Step 47. 实现统一查询表达式解析与校验
- 操作：完成统一查询表达式的解析、校验和错误提示，使其可同时服务搜索、规则和智能文件夹。
- 验证测试：输入合法与非法查询条件各一组，确认合法条件可通过，非法条件会返回明确错误位置。

### Step 48. 实现规则引擎命中判断
- 操作：在 `crates/rule-engine` 中实现基于统一查询表达式的命中判断逻辑。
- 验证测试：对一组固定文章和规则执行匹配，确认命中结果与预期完全一致。

### Step 49. 实现规则动作执行
- 操作：支持命中后自动标记已读、星标、稍后读、加标签、移动分组和清理候选等动作。
- 验证测试：创建一条自动加星规则并重新抓取文章，确认命中文章会自动更新状态。

### Step 50. 建立规则审计记录
- 操作：为每次规则命中记录输入、匹配结果、执行动作和时间，方便用户理解自动化行为。
- 验证测试：查看某条规则的命中历史，确认可以追溯具体文章和触发动作。

### Step 51. 实现智能文件夹
- 操作：允许用户保存查询表达式为智能文件夹，并在左栏与普通文件夹并列显示。
- 验证测试：创建一个“最近 7 天未读文章”的智能文件夹，确认新增文章后列表会自动更新。

### Step 52. 实现全文搜索与过滤搜索
- 操作：接入标题、摘要、正文和元数据搜索，并支持来源、标签、日期、状态的组合过滤。
- 验证测试：对同一关键词分别做全文搜索和限定来源搜索，确认返回结果数量不同且都符合条件。

### Step 53. 实现搜索命中高亮
- 操作：在搜索结果中展示命中片段，并在阅读面板中高亮当前搜索词。
- 验证测试：搜索一个只出现在正文中的词，确认列表摘要和阅读面板都能显示命中位置。

## 阶段 7：离线缓存、导出与批处理

### Step 54. 实现缓存策略配置
- 操作：支持全局缓存上限、按源缓存策略和“仅元数据 / 缓存正文 / 缓存正文与附件”三类策略。
- 验证测试：给两个不同订阅源设置不同缓存策略后抓取内容，确认本地缓存产物数量明显不同。

### Step 55. 实现缓存逐出策略
- 操作：实现基于最近最少使用的清理逻辑，同时保护星标、稍后读和带笔记文章不被自动清理。
- 验证测试：在缓存空间受限时触发清理，确认普通文章被清理而受保护文章仍保留。

### Step 56. 实现 Markdown 导出
- 操作：支持导出单篇文章和批量文章到 Markdown，并保留元数据、正文和批注。
- 验证测试：导出后打开 Markdown 文件，确认标题、来源、时间和正文内容完整存在。

### Step 57. 实现 HTML 与 PDF 导出
- 操作：支持导出阅读视图为 HTML 和 PDF，确保导出结果与当前阅读排版基本一致。
- 验证测试：导出同一篇文章为 HTML 和 PDF，确认两种产物都能正常打开且正文完整。

### Step 58. 实现批量操作
- 操作：支持批量标记已读、批量加标签、批量加入稍后读和批量删除缓存。
- 验证测试：一次选择多篇文章执行同一动作后，确认所有选中项都被更新，未选中项不受影响。

### Step 59. 建立错误提示与任务状态面板
- 操作：为抓取、导出、缓存清理等后台任务提供用户可见的状态、错误详情和恢复建议。
- 验证测试：手动制造一个失败导出或失败抓取任务，确认界面能显示失败原因和重试入口。

## 阶段 8：同步基础能力

### Step 60. 定义同步实体与事件边界
- 操作：明确哪些字段通过 `SyncEvent` 同步、哪些字段只保留本地、哪些内容按需懒加载，并把“User、Device、SyncEvent、EncryptedBlob、UserSettings”为服务端最小实体的约束写入架构文档。
- 验证测试：对一条文章状态变更、一个批注变更和一个正文缓存变更分别分类，确认同步策略清晰且与服务端最小实体模型不冲突。

### Step 61. 在本地实现事件日志生成
- 操作：每次用户状态、批注、标签归属或订阅结构变化时，同时生成对应 `SyncEvent`。
- 验证测试：执行一次标记已读、一次添加笔记和一次移动订阅源操作后，确认事件日志中新增三类对应事件。

### Step 62. 建立同步引擎基础
- 操作：在 `crates/sync-engine` 中实现事件批次打包、游标跟踪、失败重试和本地重放逻辑。
- 验证测试：构造一组本地事件批次进行重放，确认另一份空数据库能收敛到相同业务状态。

### Step 63. 实现同步服务器骨架
- 操作：在 `apps/sync-server` 中建立远程同步 API 的最小服务，覆盖账号认证、设备注册、事件上传、事件拉取和对象存储清单，并确保服务端只暴露加密后的 `SyncEvent`、`EncryptedBlob` 与设备元数据。
- 验证测试：让一个本地客户端完成账号登录、设备注册、上传事件和拉取空响应的完整流程，确认远程同步 API 链路可通，且服务端不直接暴露业务实体。

### Step 64. 实现冲突合并规则
- 操作：按设计文档实现字段级时间戳合并、阅读进度取较大值、高亮与笔记追加、标签集合合并和排序事件处理。
- 验证测试：构造两台设备对同一文章做不同修改，合并后确认结果符合预先定义的冲突规则。

### Step 65. 实现端到端加密
- 操作：让客户端持有主密钥，服务端只保存密文、必要索引和设备级元数据，并实现密钥恢复流程。
- 验证测试：检查服务端持久化内容，确认看不到明文文章笔记和用户状态。

### Step 66. 实现桌面端同步设置界面
- 操作：提供同步开关、账号/服务器配置、设备列表、最近同步时间和错误提示。
- 验证测试：在错误服务器地址和正确服务器地址之间切换，确认 UI 能明确区分“未配置、同步中、同步失败、同步成功”。

### Step 67. 实现 WebDAV / Nextcloud 适配层
- 操作：在同步协议不变的前提下，增加基于对象存储思路的自托管适配器。
- 验证测试：同一份本地数据分别通过官方服务端和 WebDAV 适配层同步，确认最终业务状态一致。

## 阶段 9：集成与开放能力

### Step 68. 建立集成适配器边界
- 操作：在 `crates/integration-engine` 中定义第三方桥接、稍后读服务、导出连接器和自动化入口的统一接口。
- 验证测试：用一个空实现适配器接入系统，确认核心 UI 不需要知道具体服务商细节。

### Step 69. 实现 Webhook 出站能力
- 操作：支持文章命中规则、手动分享或导出完成后向外发送 Webhook。
- 验证测试：触发一次文章分享动作，确认外部测试端能收到包含文章元数据的 Webhook 请求。

### Step 70. 实现基础 REST API
- 操作：实现本地桌面 API，只在桌面端运行时监听 `127.0.0.1`，提供只读为主的接口，优先覆盖订阅源、文章、搜索结果和导出入口；修改型操作如标记已读或加星必须有用户确认。
- 验证测试：从本机调用本地桌面 API 获取文章列表和文章详情，确认返回内容与桌面 UI 当前数据一致，并确认未授权远程地址无法访问该 API。

### Step 71. 实现知识库导出连接器
- 操作：先支持导出到通用 Markdown 目录结构，再扩展 Obsidian、Notion 或 Logseq 所需的格式映射。
- 验证测试：导出一组带标签和笔记的文章到目标目录，确认目录结构、文件命名和元数据符合预设规则。

## 阶段 10：AI 能力

### Step 72. 建立 AI Provider 抽象
- 操作：定义本地模型与远程模型共用的 Provider 接口、任务提交方式、超时与重试规则。
- 验证测试：用一个本地模拟 Provider 和一个远程模拟 Provider 分别执行任务，确认调用入口一致。

### Step 73. 建立 AI 任务队列与缓存
- 操作：把摘要、关键词、翻译和问答统一放入后台任务队列执行，并把结果写入 `AIArtifact`。
- 验证测试：为同一文章重复触发同一任务，确认命中缓存时不会重复计算。

### Step 74. 实现摘要与关键词提取
- 操作：先交付单篇文章摘要和关键词提取，并在阅读面板中作为附加卡片显示。
- 验证测试：对一篇长文执行摘要任务，确认结果被持久化，且关闭再打开文章后仍能看到摘要卡片。

### Step 75. 实现翻译与限定上下文问答
- 操作：支持整文/选段翻译，并把问答上下文限制为“当前文章”“当前来源”或“当前过滤结果”。
- 验证测试：对当前文章提问一个答案明确的问题，确认回答只引用当前允许上下文，而不是其他来源内容。

### Step 76. 实现 AI 隐私与开关控制
- 操作：让 AI 默认关闭，并明确展示发送范围、提供商、缓存删除和重新生成入口。
- 验证测试：在 AI 关闭状态下打开阅读器，确认不会自动触发任何 AI 请求。

## 阶段 11：Web 与移动端

### Step 77. 构建 Web 端只读入口
- 操作：在 `apps/web` 中实现基于账号体系的远程访问入口，首期只覆盖阅读、搜索和轻量状态修改，不承担桌面端本地优先职责。
- 验证测试：在浏览器中登录后查看文章、执行搜索和切换已读状态，确认操作依赖远程同步数据而不是本地抓取链路。

### Step 78. 将 Web 端限制在已定义边界内
- 操作：明确不在首期 Web 端实现本地抓取、完整离线缓存、复杂规则编辑器和深度系统集成。
- 验证测试：检查 Web 端需求清单，确认不存在超出“同步访问入口”定位的阻塞任务。

### Step 79. 构建移动端阅读优先壳
- 操作：在 `apps/mobile` 中建立 React Native + Expo 基础应用，只先覆盖登录/同步、文章阅读、搜索、笔记和播客消费。
- 验证测试：在模拟器或真机中打开移动应用，确认可以同步文章并进入阅读页。

### Step 80. 适配移动端缓存与媒体能力
- 操作：补齐移动端离线缓存、音频播放、后台恢复和系统分享的基础能力，但不实现复杂规则编辑器。
- 验证测试：离线打开一篇已缓存文章并播放已缓存音频，确认内容可读可播。

## 阶段 12：稳定性、发布与收尾

### Step 81. 建立解析回归测试集
- 操作：把真实世界 feed 样本固化为回归测试资产，覆盖常见成功路径和失败路径。
- 验证测试：运行解析回归测试，确认新改动不会破坏既有样本的解析结果。

### Step 82. 建立桌面端端到端测试
- 操作：围绕“添加订阅源、抓取、阅读、标记状态、搜索、导出”建立端到端用例。
- 验证测试：在干净环境中执行端到端测试，确认核心离线阅读路径可完整通过。

### Step 83. 建立同步并发测试
- 操作：模拟多设备并发修改同一批文章，持续验证冲突合并和事件重放不会产生状态漂移。
- 验证测试：对同一测试场景重复多次同步，确认最终收敛状态稳定一致。

### Step 84. 建立性能基线
- 操作：按架构文档中的数值化指标记录万级文章库下的启动时间、列表滚动、搜索耗时、批量更新耗时、正文提取耗时、抓取吞吐和内存占用。
- 验证测试：在固定样本数据上重复测量，确认启动时间 `<= 1.5 秒`、搜索 `<= 500 ms`、1000 篇批量标记已读 `<= 2 秒`、100 个订阅源冷启动抓取 `<= 30 秒`，并满足架构文档中的其余指标。

### Step 85. 完成发布与运维文档
- 操作：把构建命令、测试命令、打包方式、数据目录、备份恢复、日志位置和常见故障处理写入仓库文档。
- 验证测试：让未参与开发的人按文档执行一次完整构建和启动流程，确认不需要口头补充说明。

### Step 86. 完成首发前架构回写
- 操作：在首个桌面版准备发布前，回写 `memory-bank/architecture.md` 与 `memory-bank/progress.md`，记录最终模块边界、已落地 schema、被推迟功能和遗留风险。
- 验证测试：逐项对照本实施计划，确认已完成项、延后项和风险项都有明确记录，没有口头知识残留在仓库外。
